## What to build

1. **Registry and cutters.** `ported.json`: which languages are ported for
   which section (`tutorial`, `rootquick`, `reference`). One module that
   cuts a document into the sections under review and into units.

2. **Ledger** (`ledger.js`). For one language and one section, across a set
   of variations: every prose unit of OLD (a sentence, a table cell, a
   heading, a comment line inside a code block) against NEW for the same
   language and variation. Each OLD unit is: the same; reworded (show both);
   or missing. Each NEW unit with no OLD counterpart is added. Join wrapped
   lines before splitting sentences. Collapse repeats: the same unit with a
   different entity or field name in it is one class, so that a language's
   review list is a few hundred classes at most, not thousands.
   A reviewer then records an outcome for each missing, reworded or added
   class in a classification file per language: same meaning; restored as a
   shared sentence, a fact, a printer or a note; a named correction; a named
   unification; or dropped, with the reason. The tool reports how many are
   unclassified, and exits non-zero when that is not 0. Nothing may be
   classified by the section it sits in.

3. **Blocks** (`blocks.js`). For one language and one section: each OLD
   code block paired with its NEW block by where it stands (the heading it
   is under), then: byte-identical; identical after undoing named
   corrections; changed otherwise, with the diff written out for review and
   classified as above. Corrections are data, one entry per correction (an
   id from the catalogue, the languages it applies to, how to undo it), in
   one file. `P/probe-ref/mine/exblocks.js` and `refblocks.js` did this for
   rust and elixir.

4. **Sharing** (`share.js`). For a set of languages and a section, on NEW
   and on OLD: prose units and words that every language prints; that at
   least three quarters print; that exactly one prints. Compare across
   languages with code spans and the language's title masked. Report
   language-supplied prose two ways: at the output (words in units only that
   language prints), and at the source (words in the string literals of a
   provider's fact table and notes, given the path to the providers).

5. **Lines** (`lines.js`). From git, for a clone and the base `9aebaf9e`:
   before (per family, per language: `ReadmeQuick_`, `ReadmeTopQuick_`,
   `ReadmeRef_`, and the shared components then) and after (each shared file
   by name; per language the provider, the naming hook, any guard forms).
   Total and without blanks and comments. For the ported set as measured;
   anything about unported languages is labelled a projection.

6. **Purity** (`purity.js`). Over `Syntax_<lang>.ts`: only printing helpers
   imported; no model, `ctx$`, `getModelPath`, `target.`, `KIT`, apidef or
   `utility_<lang>`; no reserved-word list; no case change or concatenation
   on a name from the description; no operation name outside the fact
   table; no condition on what the description says is shown. Lint the
   notes: a note that contains a feature name, an option key, an entity name
   or an operation name is flagged. Over `Naming_<lang>.ts`: flag a rule the
   code generator does not share (concatenation onto the SDK name, a
   pluralisation, a reserved list not imported), and for each function the
   hook calls, show that a non-README component of that language calls it
   too.

7. **One command per language** (`portcheck.sh <clone> <out-root> <lang>`):
   regenerate (optional), ledger, blocks, sharing for that language,
   purity, the guard test, one screen of counts, non-zero exit when
   something is unclassified or impure.

8. **Before-numbers for the languages still to port that have a toolchain
