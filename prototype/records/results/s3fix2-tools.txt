  factsheet.js (READ AND RAN) reads each fact's account from the guard report (SDKGEN_GUARD_REPORT=1). For every non-enumerated string fact whose account is `language` or `convention`, it collects every NEW unit whose masked text carries the fact's label (facts.js masking).
  
  **Contexts.** Each such unit is paired with OLD through ledger.pairSection, either identical or the OLD side of a reworded pair, in the same variation. The units are grouped by context, meaning each distinct masked NEW unit:
  - **held:** some pair's OLD unit, masked with the same facts, holds the label beside the same left or right token, or is the label alone;
  - **contradicted:** it has paired OLD units and none holds the label;
  - **new:** every unit is added.
  
  **The verdict.**
  - ATTESTED only when at least one context is held and none is contradicted or new.
  - Otherwise UNATTESTED, and the sheet exits 1. `portcheck` prints `UNATTESTED <path> = <value> (<account>): <contexts>` and FAILs.
  - A record `hand/<lang>.json` → `facts: { "<path>": { value, why, evidence } }` at the current value turns it into RECORDED. A record for another value says "hand record is for ..." and does not count. `--scratch` / `SCRATCH=1` ignore these records.

enumerated_facts: |
  Enumerated facts (named, prints, entityBy, keys, and any enumeration accounted `language` or `convention`) are not printed: they choose which sentence prints.
  
  **How a wrong one shows** (in the README):
  - This language prints another value's sentences instead of its own.
  - In classes, those are reworded classes whose NEW side matches the other value's reviewed sentences and whose OLD side matches no reviewed pair. They are left for a person with that hint, and come with vanished tokens.
  - From scratch, an `added` unit can still be matched as shared. That is why the fact sheet also judges the fact itself.
  
  **The fact-sheet check (heuristic, RAN):**
  - Marker units for (fact, value): masked units printed by a reference declaring that value and by no reference declaring another.
  - Value words: words in those markers that no other-value reference prints.
  - ATTESTED when a NEW marker unit pairs with an OLD unit that is identical or uses a value word. UNATTESTED when markers are printed but none pairs that way.
  - "not judged" when no reference declares the value; elixir entityBy 'module' and rb prints 'listFields' are in this case.
  - "not printed" when no marker is printed; rb named 'bare' is in this case.
  
  **Control** (controls/factmut/py-keys-bare): py `keys` 'member' -> 'bare' fails naming ref.keys in both modes; unmutated py is ATTESTED.
  
  **Limits:**
  - At the frozen state every judged enumeration is ATTESTED, but often by a minority of units (zig named: 365 of 673).
  - A wrong value whose words already appear in the language's OLD page would pass.
  - I tested only one enumeration mutation.
