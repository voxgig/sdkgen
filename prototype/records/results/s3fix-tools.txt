classification: |
  `classify.js --lang L` goes through three sources in order.
  
  0. **Recount first.** A class that `hand/`, `pinned/` or the previous `classes/L.json` records at another count is left open (RECOUNT).
  1. **Hand entries** from `hand/L.json`.
  2. **Stage-3a rule records.** One applies only if all of these hold:
     - L is in the rule's language list (every rule has one; a rule without one throws on load);
     - the class id was classified by that rule in stage 3a, at the same count;
     - the rule's pattern still matches the class's text;
     - the outcome is valid for the class's type.
  
     A rule therefore never classifies a new id. Language lists alone are not enough: I applied the rules with `langs` only to the injected texts, and `direct-shared` (langs: the eight) still accepts py "`ok` is `True`" and go "except for a non-2xx response".
  3. **Shared sentences, matched exactly.**
     - Only `reworded` and `added` classes take part.
     - Each is masked with L's declared facts and compared with the reviewed classes of the reference languages (`ported.json` less L), each masked with its own facts.
     - An `added` class matches a reviewed NEW text; a `reworded` pair must match a reviewed OLD and NEW pair.
     - Every distinct instance of the class must match.
     - It must not be printed more often in any variation than a reference language prints it.
     - A reference class that was itself matched as a shared sentence is never used as a reference.
     - The record is `shared:<ref>:<id>`, with the reference class's outcome and how that outcome was given.
  
  Never matched automatically: `echo`, `missing`, `dangling`, token classes and changed code blocks. `ledger.js` enforces this as well: an echo must be `contradiction` (with `where`, `true` and `evidence`), `defect`, or `same-meaning` with a `why`; anything else is INVALID and counted as open. A `shared:` outcome on any type other than `reworded` or `added` is INVALID too.

masking: |
  `facts.js` reads, from the clone's compiled `dist-test-scaffold/.sdk/dist/cmp/<lang>/Syntax_<lang>.js`, every string value under `facts` and `ref.facts`. It adds the naming hook's layout names (module, client, ctor and `names.*`), computed with the clone's own `sdkDescription` and the language's compiled Naming hook on the harness's baseline model B. rb has 63 declared facts.
  
  A value is replaced by a label listing every path at which the language declares that value, for example `⟦ref.none⟧` or `⟦container|direct.returns|prepare.returns|recordType|valueType.OBJECT⟧`. Two languages therefore match only when the same slots hold their own values. Concretely, py's `True` labels as `lits.true` and can never match another language's `false`.
  
  How a short token is kept from being masked everywhere:
  - **Inside code spans, whole span only.** A span is masked only when its entire content is the value. A `{Class}`, `{accessor}` or other placeholder in a value matches a single identifier, and an operation's method may carry the `()` its `named` fact prints. A value is never masked as part of a span, so `nil`, `sdk` or `err` are masked only when they make up the whole span.
  - **Outside code spans,** only two kinds of value are masked:
    - fragment values of 6 characters or more that hold a backtick, a space or a leading `.` (the collection fragment "`Array`", `body.values`), replaced as the whole phrase;
    - single words at the slots shared code prints unquoted (`collection`, `ref.noun`, `ref.entityNoun`, `ref.maps`, read from `ReadmeRef.ts:232,310,153` and `runtimeprose.ts:41`), as whole, case-sensitive words. The English word "list" in a sentence is never touched.
  - **In code comments,** only values with a non-letter character and 3 or more characters (`data_get`, `.ok`, `Data()`), as whole tokens.
  - **Enumerations are never masked:** `named`, `async`, `result`, `prints`, `entityBy`, `keys`, `cancel`, `prepare.fails`, `unusedError` and every `kind`. They choose which sentence is printed, so "throws" and "raises" stay distinct sentences.
  
  After facts, model names are masked as before (entities, fields, the SDK name, the language title), but numbers are not, so a `2` to `3` change is never masked away.
  
  Known gaps in the masking:
  - A label is strict: one value declared at different paths in two languages does not match. ts declares `DemoSDK` as both client and ctor; rb's ctor is `DemoSDK.new`.
  - go's collection `[]any`, printed unquoted inside a comment, is not masked.
  - The layout comes from model B only.
