  The proposal is neither a general solution alone nor just a list of fixes.
  
  It is a general mechanism for the per-language documentation text. At twenty languages it worked there:
  - 34 of the 36 in-scope entries in the three sections were fixed by shared code alone for all twenty languages.
  - A correction made once reached every page.
  
  It is not a general solution to the catalogue:
  - It reaches 66 of 329 entries (20%).
  - A quarter is already written once but needs shared derivations the proposal does not supply.
  - Just over half (consumer writers, generated source, tools, docgen, create-sdkgen, apidef, the pack) stays individual fixes.
  
  Writing a sentence once also makes it a claim about twenty runtimes. The build kept finding shared sentences false for some runtime, the last false in 17, and the checks it built do not see that kind of error.
  
  The principle that spans more of the catalogue is one resolved answer per fact, read by every writer. Writing each sentence once is that principle's documentation half.
