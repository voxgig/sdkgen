A classification is keyed by a 10-hex class id only; a section name is rejected with an error. handoff: |
  To check a port, run `cd <v3tools> && ./portcheck.sh <clone> <out-root> <lang>`, where `<out-root>` holds `old/` and `new/`. Use REGEN=1 to regenerate new/ from the clone; alias-go2 is generated only from a clone copied under v3tools. Work the worklists in review/<lang>/:
  - `*.ledger.txt`, with the order dangling, echo, missing, reworded, added, tokens;
  - `*.blocks.txt` and `*.blocks.diff`.
  
  To record a review, copy entries from `*.template.json` into `classes/<lang>.json` with an outcome. Keep `n`, so that a regression that later joins a class you reviewed comes back as RECOUNT.
  
  Declare each correction once in corrections.json (id, languages, sections, undo regexes) rather than classifying every block it changes.
  
  When a language is ported, add it to ported.json `ported`; nothing else holds a language list.
  
  The before-numbers for js, rb, php, perl, java and cpp are in before/lanes-old.log and before/lanes-old-php.log. Rerun them on a NEW clone with `before/run.sh <clone> <lang>` and compare: rb, php and perl execute their examples; java and cpp only check structure; js has nothing to run.
  
  `node recall.js` and `node inject.js` are the regression tests for the tools themselves. After changing a tool, they should still report 49 of 51 flagged and 4 of 4 injections flagged.
