## Verdict

§W The five hypotheses were fixed before anything was built (section 1.3). For each, below: the claim, the criterion as fixed, the figures at twenty languages with who measured them and whether they were run or read, and one word. **Refuted**: the criterion is crossed. **Holds**: it is not crossed and the claim is shown. **Not refuted**: the criterion is not crossed, but the claim is not fully shown. **Not decided**: the evidence does not settle it. None of the five is "not decided". Where the independent measurer or the attacker differs from a builder's figure, the verdict follows the evidence that survived, and says so.

§W The finding that matters most for every verdict below came from the attacker, and every check the prototype has passed it. A sentence that shared code writes once, "- Also attaches to pipeline hooks.", prints under the `secrets` feature on every REFERENCE page. Shared code writes it because the feature's model declares a `PreSpec` hook. Only ts, js and py define that hook; the other seventeen runtimes resolve the secret at the transport, and several say so in their own comments (csharp: "NO PreSpec OVERRIDE, deliberately, though the model declares the hook"). The sentence is false in 17 of the 20 languages. The guard, the review tools, the catalogue checker and the integration all passed it; the integration accepted it for the seven new languages by a written rule, without reading their runtimes. The second half of the same finding: a porter who leaves out an optional fact (the stream signal in csharp, java, kotlin and scala; the deleted mark in js) loses a true sentence from every page and passes everything, and leaving out two others (php's cached accessor, cpp's remove that keeps its data) brings back a sentence already known to be false for that runtime, shown only by one open class that a person decides. The rule the prototype adopted after its first wave, that a wrong or vanished sentence must fail in the guard or the tools before any person reads it, does not hold at the frozen state.

### H1. One shared component plus one provider per language

§W - **Claim.** The README quick start and the REFERENCE page can be written as one shared component plus one syntax provider per language, for all 20 languages.
§W - **Criterion.** Refuted if providers for 3 or more languages have to read model facts or carry model-dependent conditions; or per-language prose that cannot be shared exceeds about 15% of the sections' prose; or the provider interface needs more than about 10 breaking changes after the first four languages.
§W - **At twenty.** Model reads in providers: 0 open findings in all twenty, 41 accepted with reasons (measurer, ran). Per-language prose over three sections and 21 variations: at most 7.1% by source and 14.8% printed by one language alone, both go (measurer, ran). Breaking changes since the first four languages: 44, of which 25 to the provider interface and 19 to the forms framework the guard reads; the newly ported languages caused 9 to 11 of them, 6 to 7 in the first wave of ports and 3 to 4 in the second (measurer, re-counted from the code history: ran over the type history, read in the commits).
§W - **Verdict: refuted**, on the interface criterion, at four times the limit. The integrator counted 4 breaking changes caused by the last seven languages and none to the provider types; the measurer and the attacker each found the interface field of the migration round to be breaking in effect (a provider without it is served the previous interface and loses sentences, and all seven new providers had to add it), and the re-count found guard tightenings that earlier records left out. The verdict follows the re-count. The other two criteria are not crossed, although the `secrets` sentence above is shared code reading a model fact where a runtime fact was needed.

### H2. The source shrinks at least 2x

§W - **Claim.** The source shrinks substantially.
§W - **Criterion.** Refuted if less than 2x fewer lines for those sections.
§W - **At twenty** (measurer, ran, with the arithmetic the base builder used at thirteen, unchanged). Documentation code: 15,038 lines before, 7,285 after, 2.06x (2.14x without the 259 lines of shared migration machinery). With the forms files the guard reads: 9,780, 1.54x. With the shared guard: 12,520, 1.20x. The tools' own headline (keeps `ReadmeTop.ts`, counts the forms, leaves the guard out): 1.50x. The thirteen languages recomputed at this state: 1.71x, 1.33x, 0.97x.
§W - **Verdict: not refuted**, by 3%, on the count the criterion names. At nine and at thirteen languages every count was under 2x; documentation code passes at twenty because twenty languages' old components are measured against shared code written once, and it came in lower than both projections made earlier (2.16x and 2.26x). On every count that includes what each language must write for its declared facts to be checked, the source shrank 1.2x to 1.5x, so "substantially" is not shown for the structure as it had to be built.

### H3. Catalogued issues fixed once, for every language

§W - **Claim.** The catalogued issues in those sections are fixed once, for every language.
§W - **Criterion.** Refuted if more than about 10% of them still need a per-language edit.
§W - **At twenty.** The catalogue checker over all 26 variations and all twenty languages exits 0: none of the checked defects shows on NEW (measurer, ran; the integrator ran 25 of the 26). The seven last ports added one provider line each for S13 and no line for any other entry. Of the 36 in-scope entries that are fixed or due: 34 by shared code alone, S13 by one declared fact per provider, D26 half (its rows for `extend` and `utility` need a declared fact per runtime). Per entry: 2.8% to 5.6% by the brief's rule, 5.6% to 8.3% strict, 16.7% to 19.4% on the strictest reading, which counts the type printers the brief exempts; per distinct defect, 3.4% to 6.9%, 6.9% to 10.3% and 13.8% to 17.2% (measurer, ran; unchanged from thirteen).
§W - **Verdict: not refuted.** The criterion is not crossed by the brief's rule on any count, but "fixed once" is not shown: the `secrets` sentence came from the shared edit that fixed X3, every check passed it, and the checks are word patterns that the H3 checker and builder fooled in other words 13 times (sections 3.3 and 5.1). Charged to X3 as needing a declared fact per runtime, the share is 8.3% by the brief's rule and 11.1% per entry (13.8% per distinct defect) on the strict reading, which is over the line (this record's arithmetic).

### H4. Examples still compile and run

§W - **Claim.** Examples still compile and run.
§W - **Criterion.** Refuted if an example test fails, in a language with a toolchain here, for a reason intrinsic to the approach.
§W - **At twenty** (integrator, ran at the frozen commit; the attacker re-ran every NEW lane with identical results). ts 16/16, go 12/12, py 12/12, c 6/6, rust 6/6, rb 49/49, zig 6/6 and cpp 6/6 in the repository's lanes; perl and php in three models, three runs each, exit 0; java: every block of three models compiles (24, 19, 19) and runs as OLD does under the test constructor; kotlin: 0 errors in three models, through the Kotlin compiler in gradle's offline cache; js: 24/24, 17/17 and 17/17 programs run as written (OLD 20, 13, 13).
§W - **Verdict: holds**, in those thirteen languages. The failures the last wave found (js's mixed module forms, which OLD shares; java's `Map.of` with a null; kotlin's missing import in one variation; scala's comparison of an object with a primitive; csharp's duplicate local name in 5 of 21 root quick starts) were each a printer choice or a naming decision, fixed inside the interface or by an optional fact; the scala and csharp ones were read, not compiled. Seven languages were never compiled, the lanes compile their own models rather than the 21 review variations, and some lanes are blind to a dropped import or swapped arguments (section 3.4).

### H5. Existing projects, packs and aliases move safely

§W - **Claim.** Existing projects, packs and aliases can move to it safely.
§W - **Criterion.** Refuted if retiring per-language components cannot be made safe for `doctor`, `remove`, `target add` and `package update` without breaking their rules, or a pack's targets stop generating.
§W - **At twenty.** The measurer rebuilt the fixtures from scratch (the earlier ones had been deleted) and re-ran every row and the three states the second attack had found unsafe: every row has its earlier verdict; the edit equal to an older release is now kept, and a release that skips its retired list is now caught at release and by `doctor`; a project with all twenty targets upgrades with its 60 retired copies removed and its 40 pages and root README equal to a fresh project's (ran). The language pack's suite passes against the frozen state, 74 of 76 with 2 skipped, and its targets generate (attacker, ran). Providers written for the previous interface keep generating, with a warning.
§W - **Verdict: not refuted.** Every unsafe state found traces to one rule with a local fix, and packs keep generating. As built it is not safe throughout: a provider that takes the interface constant by a deep import passes every later raise unread (open, and the remedy recorded for it is ruled out by sdkgen's own `package.json`); the fix for a skipped list makes `doctor` fail a consumer target's own component, which the repository documents as a safe extension (attacker, ran); and an interface raise, restored files and a pack across a raise were not re-run at the final state.

### The maintainers' first question

§W The maintainers asked whether the proposal is a general solution or a list of individual fixes. On the evidence, it is neither alone. It is a general mechanism for one part of the problem, the per-language documentation text, and at twenty languages it worked there: of the 36 catalogue entries in the three sections built, 34 were fixed by shared code alone for all twenty languages, and a correction made once reached every page. But it is not a general solution to the catalogue. Its mechanism reaches 66 of the 329 entries (20%); a quarter of the catalogue is already written once and needs shared derivations of facts the proposal assumes and does not supply; and just over half is consumer writers, generated source, the generator's tools, docgen, create-sdkgen, apidef and the language pack, which stay individual fixes (section 4). And writing a sentence once makes it a claim about twenty runtimes: the build kept finding shared sentences that were false for some runtime, the last of them false in 17, and the checks it built do not see that kind of error. The principle that spans more of the catalogue is the one the proposal's first point restates, one resolved answer per fact read by every writer; writing each sentence once is that principle's documentation half.
