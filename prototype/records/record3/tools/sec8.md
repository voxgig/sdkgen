## 8. Not done

The prototype is finished. What follows is what it left undone: what was
recorded and not made, what was never measured, and what a real adoption
would still have to do. Nothing in this list is in progress.

**Found by the attack on the frozen state, and not fixed**

§W - The `secrets` sentence, "- Also attaches to pipeline hooks.", false in 17 of 20 languages. Made true, it needs a declared fact per runtime or no sentence; either way the model's own declaration of a `PreSpec` hook, which seventeen runtimes contradict, needs a decision.
§W - An optional fact left out leaves no trace (the stream signal in csharp, java, kotlin and scala; the deleted mark in js), or brings back a sentence known to be false with one open class to show it (php's cached accessor, cpp's remove that keeps its data). Nothing requires each optional fact to be declared, present or absent.
§W - In java and kotlin the REFERENCE operation blocks bind the result as `Object` or `Any?` with no cast, beside the sentence that `data()` reads its record. The integration recorded the opposite as its reason not to add a declared-type fact.
§W - The derived list of shared sections makes `doctor` fail a consumer target's own component (section 3.5); the `package check` error for an unservable interface was removed with the c5 change; the deep import of the interface constant still bypasses the version check, and the remedy recorded for it (an exports map) is ruled out by the repository's own `package.json`.
§W - Three of the integration's changes have no test that fails without them (the deleted read's layout fill, the rule that a declared call factory occurs in the runtime, the csharp and java citation pins). Java, kotlin and scala still have code-valued citations without a value pin.
§W - Seventeen of the prototype's earlier commits (fifteen in sdkgen, two in the tools) end in an attribution trailer and a session link that the prototype's own rules forbid; none is on `main`, and none should be carried there as it stands.

**Recorded at the integration and not made** (each with what it would take in the integrator's record)

§W - Optional facts: a declared return type that needs a cast (java, kotlin, scala, csharp); a runtime with no built-in live transport (cpp, ocaml, zig); the thrown type in the throw-style sentences (cpp and others); the stream signal's form for java and scala, and, by the attacker, for go, perl, clojure, swift, elixir, ts and js too.
§W - Shared code: **Returns:** for entity members (php declares returns the page never prints; adding it changes every page that declares them, so breaking); php's case-folded class names (latent: no variation has two names that fold together); a separate fence for signature blocks (js prints TypeScript notation under a js fence); the operations a section uses passed to the imports printer (java imports `java.util.List` where nothing is listed).
§W - Guard and tools: a member's receiver judged by name where instance and type share `.` (java, kotlin, scala, csharp); a static signature compared with its declaration; `arity` required where a list has required parameters (breaking: it forces c, clojure, elixir and ocaml); key sets of direct's and prepare's returns compared; citation tokens matched as whole identifiers; constructor optionality compared; the rendered call checked for `await`; a catch type checked against what the runtime throws; a forms claim of parenthesis-free calls compared with the runtime; the getter copy fact required on every getter; an enumerated fact attested only where its value prints differently from every alternative; calls with a block argument read by the printed-call check; a scope checker for C#.
§W - The csharp lane that passes when dotnet is missing should skip visibly.
§W - The porting guide's corrections, recorded by the porters, reviewers and fixers of both waves for its owner.
§W - Unported README components outside the three sections: the direct how-to sentence about `err` in twelve languages; D26's rows for `extend` and `utility`; the JavaScript spelling of every default in the feature tables; cpp's test-mode promise and its TypeScript error-handling examples; js's `require` in its module-structure section.

**The catalogue (H3)**

§W - D26's other half: rows for `extend`, `utility`, `entity` and `test`, and a default column. `extend` and `utility` need a declared fact per runtime; `entity` and `test` were not established either way.
§W - U37 was decided and left: the go title follows `target.title`. U44's two leftover guard exceptions remain in py and elixir.
§W - The 17 attempts to put a fixed defect back in other words were not repeated at twenty; the checks those attempts fooled were strengthened only where a post-attack variant was added.
§W - The language pack was generated against the frozen state only by its own suite (74 of 76 pass, 2 skipped); its pages were not compared with its pages before the catalogue edits.

**Migration (H5)**

§W - States not re-run at the final state, because the release builds and scripts they need had been deleted: the interface raise (three states), restored files after an update, the previous-interface page against 3.2's own output, the nine provider mutations, and thirteen of the second attack's other states.
§W - Never run by anyone: edition components retired end to end; a pack that ships providers carried across a real release that raises the interface; a version for the naming hook; a project made by create-sdkgen and generated with `npm run generate`.
§W - The layer that serves the previous interface serves one version only; nothing ties it to a number of releases. A stricter variant that makes omitted optional facts and printer arity loud for a provider declaring the current interface was built on a side branch by the migration builder and never had its suite run.
§W - `target remove` still refuses an unrecorded edited copy with the wording "did not write", which is inaccurate for a copy an add wrote. The CLI's one-line drift summary still omits the retired, outdated, damaged and orphan counts.
§W - The frozen package reports 4.44.0, because the migration round's version commit was left out; every release must now regenerate the retired list, which the publish workflow's tests check against the release tags.

**Never measured**

§W - Compilation or running of any example in csharp, scala, swift, lua, clojure, elixir and ocaml; the root quick starts of c, rust, zig, cpp and kotlin run from a repository root; most changed blocks of the 21 review variations, which no lane model produces.
§W - A verdict for 164 of the 385 distinct shared sentences at twenty, which no independent reader has given; the 40 sentences printed by one language that the tools could not explain were read by the measurer and not traced to their templates.
§W - The other ten README families, the language pack's own documentation components, real specifications, and the cost of keeping shared sentences and declared facts true as runtimes change over time.
§W - Whether the staleness checks' known holes matter in practice: the builder of the tools round beside the 3.3 freeze beat them with five of six attacks, and none was fixed.

**Carried from earlier rounds, still open**

§W - Facts recorded and not yet expressible: ocaml's `e_deleted` marker and operation parameter names; lua's whole-record print in the root quick start; ocaml's stream kind.
§W - The runtime defects of section 5.7 are recorded, not fixed (except the ts and js test fallback). The pages of `main` listed in section 5.8 are unchanged on `main`.
§W - Hand records of classes that no longer exist were not pruned in any language; they have no effect, since the one command reads only classes that exist.
§W - The catalogue's open borders (section 4.4) are carried as ranges; no family beyond the three sections was built to settle a package's fate.

**What a real adoption would still have to do**

§W - Bring the description, the example representation, the shared sections, twenty providers and naming hooks, and the extracted naming functions onto `main`, and retire sixty per-language components there; and the migration machinery with its release step.
§W - Bring the guard and the twenty forms files into the repository's tests, and decide what replaces the review tools and the hand records, which are working files of the prototype and not code its CI can run. Without them, a declared fact and a shared sentence are checked by nothing.
§W - Settle the interface's versioning: a window of releases for the served previous version, and the check that cannot be bypassed by a deep import.
§W - Decide, family by family, whether to port the other ten README families or accept that ported and unported sections of one SDK contradict each other until they are.
§W - Port or keep the language pack's own components, and settle with the pack's maintainers how a pack meets an interface raise.
§W - Do the plan's work that the proposal does not replace: the derivations and the text guard (WP19, WP03) and the 35 packages that stay (section 4.3).
