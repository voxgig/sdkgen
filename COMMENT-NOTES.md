# Implementation rationale

Generator components and templates have different roles. Components render model-dependent structure; templates provide source shared across APIs. Slot and insertion comments are generator inputs, so they must survive comment cleanup.

Entity operations return entity instances. Generated flow tests and typed accessors read record data through the instance's data accessor. A compiled generated test tree checks this boundary more effectively than text assertions alone.

Raw request helpers remain private behind the operation-specific permission checks. GraphQL error arrays must be interpreted even when the transport status is unsuccessful, so the server's diagnostic is retained.

Feature ordering determines transport composition: the mock transport is installed before wrappers that delegate to the current transport. Preserve that order when adding or adopting feature instances.

Vendored dependency sources are pinned snapshots. Their comment policy is enforced in their upstream repositories; update the snapshots through the vendoring workflow rather than editing them independently.

The text a neutral document prints from the model is escaped once, by the `escape` rule in the fact rules, and each component reads the form its context needs: a table cell, inline text, a code span, a link target. The pass supplies each raw text as the document prints it and writes the forms beside what the text describes. `rep` stands in for a Markdown escape aontu does not have yet. Text from the spec loses its relative links, which resolve against the spec's site rather than the generated repository, and its fences, which every README example test would extract and compile; the project's own text keeps both. `$$` is rewritten everywhere because the template pass would read it.

Sources: [agent guide](AGENTS.md), [SDK template](ts/project/.sdk/src/cmp/ts/fragment/Main.fragment.ts), [generated compilation tests](ts/test/generatedcompile.test.ts).

Target model files describe supported capabilities and retired output paths. Project-specific publication values belong in the project overlay, which survives target replacement. Concrete model values do not override conflicting concrete values; leave project-owned keys unset in target fragments and use schema defaults.

An operation context builds its own control. A context created with an operation name does not inherit the control of the context it was created from; one created without a name still does, so an entity context continues to share the client's. That single condition is what keeps paging cursors, actors and explain records from leaking between independent calls, and it is the reason a caller who wants continuation must pass the same control object again. The condition is spelled the same way in every target, and the reference implementations carry the comment; the rest read as an ordinary guard beside it.

Paging parity is read per port, not per file. Most targets carry a paging file of their own, but clojure and ocaml hold their whole feature set in one aggregate file, so a sweep across per-feature template paths never reached them and both drifted unnoticed: neither read the underscore spellings, neither preferred the next page over the current one when building the request, and neither wrote the record back into the call's control object. The parity suite therefore enumerates the PORTS and has each one declare where its paging lives, so a new target fails until it does the same. Two of its checks need care for the same reason. A next-page name proves nothing on its own, because it is also a key of the record the result stage builds, so the check matches it beside the write of the page query parameter and reads a short window rather than one line, since the selection wraps in the wordier ports. And the write-back check matches the control and paging on one line, because every port spells its control differently.

A removal compares the source of the item it is removing, whatever the model says about it. The drift check writes off an inactive feature's copied source as stale, which is correct for a project that deactivated a feature and left the files behind — but it made `feature remove` refuse its own removal, because every file the removal was about to delete came back as drift. Naming the feature the caller is acting on compares those files against what the add wrote instead, so a project EDIT still refuses and a merely deactivated feature removes cleanly.

A C program has one flat symbol namespace, so every global name a generated C SDK defines carries the SDK's prefix, and two SDKs link into one program without one binding to the other's code. The names are read off objects compiled once without the prefix, never listed: a list would miss the vendored payloads, which arrive from struct, sekreto and other packages' features, and would drift with every template. A generated header renames definitions and calls alike through the preprocessor, so the vendored sources stay as vendored, and the archive is read back to prove that nothing escaped. Static linkage cannot do the same work, because every template global is declared in the umbrella header and called across translation units. A program's own code is renamed only for the names the SDK's headers mention: the full map renames every matching identifier, so a program's function named like a private payload name, such as `fail`, would silently become the SDK's own and bind to it.

The C target's transport is written in-tree and takes its TLS from the platform's OpenSSL, unvendored and unpinned: cryptographic transport is never written here, and everything else C's library lacks is. A handshake verifies the chain against the system store, verifies the host name or the IP literal, sends SNI only for a name, and treats a CA bundle as additional roots. A pin replaces the store with the one pinned certificate, which the name check still applies to, and it is compared during the handshake, before a byte of the request is written. Its reads and writes go through the transport's own socket calls, so the deadline and the SIGPIPE handling hold inside TLS, and a build without OpenSSL links no TLS library at all.

A documented example compiles as the body of a function that is given only the names it uses and does not declare, because C# refuses a local that shadows one in an enclosing scope, and the other languages lose nothing by the same rule. Each language's wrapper follows its own grammar. The C# examples live beside the SDK rather than inside it, because the SDK project compiles every source file below its own directory and would take them as its own. The Scala wrapper opens each block with `locally`, because a brace that opens the line after an expression is that expression's argument. The Clojure wrapper gives each page a namespace of its own and runs each block's `require` forms at the top level ahead of the function that holds the rest, because an alias has to exist when the function is compiled, and because an alias one page requires must reach no other page; within a page a block sees the aliases required before it, since a clojure section requires an entity's namespace once where the other languages reach the entity through the client. Loading the files compiles every function without calling one, so every symbol resolves and no arity is checked, and that is the whole of what "compiles" means there. The C# and Swift wrappers give each block a file of its own, because their imports are file-scoped and nothing in those pages is shared between blocks. Each lane also has to refuse a block that calls a method the SDK lacks, naming the method, because every toolchain reports a build with nothing to compile as a success.

A feature table keyed by a string a caller supplies, such as the cost feature's actors, cannot be a plain object in ts and js: the key `__proto__` reads the object's prototype, so the increment that follows lands on `Object.prototype`, and `constructor` lands on `Object`. Tables that callers read back by key, as the reference shows, have a null prototype, so the documented bracket access keeps working; a table nothing reads by key outside the feature is a `Set` or a `Map`. The ts and js corpus runners check after every case that neither shared prototype gained a property, and they build each case with defined rather than assigned keys, or a `__proto__` key in the fixture would vanish before it reached the assertion.

A feature that marks a call as already recorded keeps the mark on the call's own context, never in a table on the feature, because the feature lives as long as the client and a table keyed by context keeps every finished call. Removing the entry at `PreDone` is not enough for the audit feature: a non-2xx reaches `PreDone` and then `PreUnexpected`, and an entry removed at the first would let the second record the call again. Where the context has no open map, as in cpp, it carries one for exactly this. A table keyed by an address, as perl's `refaddr` gives, is also wrong for a mark: a finished call's address is reused, so a later call reads as already recorded.
