## Working rules the user set

- **Merge when green.** A pull request opened for this work merges once CI
  passes on every OS and no review thread is open.
  - Codex reviews every PR in sdkgen, apidef, struct and sdkgen-langpack,
    usually within 15 minutes of it opening or being marked ready. A later
    push is not reviewed again unless someone comments `@codex review`.
  - Wait for that review before merging: it found real defects in most PRs.
- **Verify every review finding.**
  - A real finding is fixed with a test and a negative control.
  - Reply on each thread as the last write before the push that fixes it,
    then resolve the thread.
  - A finding that does not reproduce gets a reply saying why.
- **Merge commits.** sdkgen, apidef, struct and sdkgen-langpack PRs merge
  with a merge commit, and a branch takes main by merging it, never by
  rebasing. apidef-validate PRs are squashed.
- **Releases wait for the user.** See [Releases](#releases-waiting-for-the-user).
- **apidef commits** carry no trailers and no tool identifiers.

457 flow steps that differ, across the 15 definitions. The issue has the
tables.

What this session added to it: the validator's Go suite passes because it
compares 112 model goldens and 30 guide goldens and skips 759 registered gaps
(`goldenSkips` in apidef-validate's `v1/go`). So a green Go suite there is
not parity; the comparison has to be rebuilt as the issue says.

## Notes for the next session

- **Check the environment rather than assuming it.** Run the `command -v`
  loop in AGENTS.md before deciding what can be verified; what one container
  had says nothing about the next. Where a toolchain is missing, these
  installs worked here: zig by `pip install ziglang` and a wrapper on `PATH`,
  lua 5.4 with busted by apt `lua-busted` and `update-alternatives --set
  lua-interpreter /usr/bin/lua5.4`, phpunit by composer into scratch space
  and a symlink onto `PATH`, pytest and requests by pip, the libssl and
  libcurl headers by apt, and vale by `make vale-install`, which lands in
  `.vale/bin` and is not on `PATH` (`PATH=.vale/bin:$PATH make scan-prose`).
  luarocks could not fetch GitHub archives through the proxy. For the
  packaged targets: dart from the stable SDK zip in Google's `dart-archive`
  bucket, unpacked and put on `PATH`; lean 4.32.1, the version the generated
  `lean-toolchain` names, from its release zip at `releases.lean-lang.org`;
  ghc 9.4.7 from apt, which builds the haskell SDK from boot packages
  alone. The clojure CLI from `download.clojure.org`'s `linux-install.sh
  --prefix <dir>`, scala-cli from its GitHub release, and swift from
  `download.swift.org`'s Ubuntu 24.04 release tarball, unpacked and put on
  `PATH`. scala-cli's native launcher ignores `JAVA_TOOL_OPTIONS`, so behind
  the proxy it needs `-Djavax.net.ssl.trustStore=/etc/ssl/certs/java/cacerts
  -Djavax.net.ssl.trustStoreType=JKS` on its own command line, which a
  wrapper script ahead of it on `PATH` can add.
- **This container sets no locale,** and tools that decode with it read
  less than a GitHub runner, which sets a UTF-8 one. A generated haskell
  SDK ran 236 SDK checks here and 253 on the runner until
  voxgig/sdkgen-langpack#40, and Ruby's `JSON.parse` once rejected a
  non-ASCII file (the next note). When a count differs from CI's, rerun
  with `LANG=C.UTF-8 LC_ALL=C.UTF-8` before reading it as the change's.
- **A gem installed for one job can break another.** `gem install rubocop`,
  for voxgig/struct's ruby lint, brought json 2.21.2 beside Ruby 3.3's
  default 2.7.2. With this container's locale unset, its `JSON.parse`
  rejected the non-ASCII media cases file and the rb media lane failed;
  `gem uninstall json -v 2.21.2` restored it. CI runs with a UTF-8 locale.
- **The struct suites** read the shared corpus through `OMNI_HOME`, a
  checkout of voxgig/omni. Composer could not download here, so the php port
  ran under a phpunit from scratch space with `--no-configuration`.
- **An apidef field-step fixture with one object-valued property** reads as
  an envelope, and its fields come from inside it; give such a fixture a
  plain `id` beside the property under test.
- **Load.** Two full sdkgen suites at once on a 4-CPU container pushed the
  load average past 10. Run one heavy job at a time. The container restarted
  three times during this session and killed every background process;
  files on disk survived, so write logs, re-run what died, and push a branch
  before a long run on it.
- **Lean's compiler has a heartbeat limit.** Four new checks written inline
  in `TFeature.lean`'s `main` failed to build with "(deterministic) timeout
  at `LCNF compiler`"; the same checks in a def of their own built.
- **Node 22's default reporter** prints `# skipped N`; the spec reporter
  prints `ℹ skipped N`. `skipped()` in `livegenerated.test.ts` reads both.
- **PHP records exception arguments** (`zend.exception_ignore_args=0`) when
  no php.ini sets otherwise, as a Homebrew install and the windows-latest
  runner do; the production ini sets `On`, as ubuntu-latest does. An error's
  trace then carries every argument the failing frames were handed, the
  context included. clean strips them; the sweep now exercises that (#326).
- **The apidef corpus survey**, required for every apidef change that alters
  a model, as this session ran it (the scripts were in scratch space). It
  runs in apidef-validate's `v1`, once per side (main and the branch, each
  built with `npm run build` in its `ts/`). A side's Go step compares
  against whatever goldens are in the working tree, so each side runs all
  of its steps before the next side starts:
  1. Start the side from the committed goldens: `git checkout -- model
     guide && git clean -fd -- model guide`. The checkout alone leaves any
     golden the other side's run added as an untracked file.
  2. Point `node_modules/@voxgig/apidef` at that side's `ts/` and run
     `UPDATE_SNAPSHOTS=1 node --enable-source-maps --test
     --test-name-pattern="model-case|guide-case" "dist-test/**/*.test.js"`.
     Copy `model/` and `guide/` aside, into a fresh directory per side.
  3. With that side's goldens still in the working tree, in `v1/go`: `go
     mod edit -replace github.com/voxgig/apidef/go=<side>/go`, then
     `GOFLAGS=-mod=mod go test -count=1 -run
     'TestValidate/(model-case|guide-case)' ./...`, and restore `go.mod` and
     `go.sum`. Because each Go run compares against its own side's TS
     goldens, a difference between the two ports shows as a failing subtest
     on one side only.
  4. After both sides, restore the checkout as in step 1, so the next
     survey does not start from a side's leftovers, then `diff -r` the two
     copies.
- **Maven Central** answered the kotlin lane with HTTP 429 once. An existing
  gradle cache, used offline, got past it.
- **apidef's Go golden tests** need an apidef-validate checkout. Set
  `APIDEF_VALIDATE_DIR` to its `v1`, or they skip; with the committed goldens
  behind main (voxgig/apidef#145 changes them), they fail for that reason
  alone.
- **GitHub runs a PR's CI on its merge with main.** A PR that conflicts with
  main runs only the push-triggered comment check, so merge main first.
- **The generate suite's `SMOKE` guard** matches generated test text: adding
  a test that legitimately calls an op with arguments can trip a coarse
  regex, as ocaml's `e_load` did; narrow the regex to the bare call rather
  than drop the test.
- **A re-review is one comment away.** Codex reviews a PR once, when it
  opens; after a large fix push, `@codex review` on the PR brings a second
  review within ten minutes. On #327 it found a real defect the fix had
  missed (clojure's stream) and one non-reproducing finding. Ask for it
  after any push that touches many targets.
- **A push that produces no build runs** means the PR conflicts with main:
  only the comment check runs. Merge main, rebuild `ts/dist`, regenerate the
  golden with `npm run golden`, push. The `ts/dist` and golden conflicts are
  always resolved that way, never by hand.
- **The mock's match treats a `$`-prefixed key as required.** The struct
  `select(list, '$x')` returns the whole list, so the ts and js mocks' match
  builder took `$body` as a required match key, and would take `$action`.
  The mocks now build their match from the record without `$body`; `$action`
  through the mock's update is a latent case of the same thing.
- **The comment gate counts density per file** (12% of code lines) and flags
  a number word in a comment (`two classes`) as a count claim. Adding a
  comment to a file near the limit trips it; trim rather than argue.
- **The generate fixture needs a `Basic<Name>Flow` per entity** for the ts
  and php test components, and the base fixture already has an entity named
  `record`. `namedEntity()` in `generateharness.ts` writes a list-only entity
  with its flow.
- **A stream-capable target is found by its transport, not its media file:**
  clojure accepts an `InputStream` in `core.clj`. Grep every target's fetcher
  for the stream type before claiming a list is complete.
- **`pkill -f <pattern>` matches the shell running it** when the pattern is in
  that shell's own command line, and kills it; `pkill -f "mt2-verif[y]"`
  does not.
- **A shared `node_modules` falls behind the lockfile.** Worktrees here
  shared one `ts/node_modules` through a symlink; after #327 raised the
  apidef peer to 8.23.0 it still held 8.18.0, and the two npm packaging
  subtests failed in every local full suite while CI, installing from the
  lockfile, was green. `npm install` in the checkout that owns the directory
  fixes it; check `npm ls @voxgig/apidef` before reading a packaging failure
  as the branch's.
- **A `py_compile` syntax check writes `__pycache__` into the scaffold,** and
  the junk filter then fails `nothing in the shipped scaffold is junk`.
  Syntax-check a copy, or remove the directory before running the suite.
- **Codex finds more on every round of a twenty-target change.** #331 took
  twelve reviews and twenty findings, each round reading the previous fix;
  budget a round per push, and expect a finding to be posted twice now and
  then (answer and resolve both threads).
- **The action-strip guard reads 60 lines after a function's definition**
  (`siteText` in `actionstrip.test.ts`) for the `$action` mention. A
  `prepareQuery` that grows past that fails the guard for its target; keep
  the function compact rather than widen the window, which would let a later
  function's mention stand in.
- **The comment gate's `narrative` rule** flags "the plan", "by design",
  "deliberately", "used to" and the like in a comment, beside the 12%
  density rule; a test's explanatory comment trips it as readily as source.
- **`gofmt -l` on the go templates lists twelve files on main.** Compare
  against main before reading a listed file as yours.
- **The swift secrets lane can crash `swift-package` on ubuntu-latest**
  (a segmentation fault with a register dump in the log). It is the
  toolchain, not the change; one re-run was green.
- **A cookie header is read one piece at a time.** Three rounds of #331
  parsed `&` inside a cookie to replace the pairs a map argument had written
  there, and each round found a caller's opaque value the heuristic broke.
  OAS 3.1.1 Appendix D settles it: cookie-pairs are delimited by `; `, and
  the form style's `&` is "always incorrect" for several values. The SDK now
  writes every pair as a cookie of its own and never reads inside one.
- **A deadline has one honest shape.** The worker stamps a response or a
  failure when it finishes; a stamp after the deadline is a timeout; a
  request unanswered at the deadline is a timeout; the instant between a
  stamp and its publication cannot be closed and the verdict never reads an
  unpublished stamp. go lands the deadline and the response in one channel,
  first in first out, so no `select` chooses at random. A test of the
  arrival judgement needs a clock that answers by thread (0 for the caller,
  later for the worker); in go, by whether the transport has run, with the
  caller's reads made before the worker starts.
- **Reaching the network.** apt reaches the Ubuntu archive through the proxy;
  a `git clone` of a voxgig repository needs the session's repository scope
  widened first.
- **Events wait in the notification queue while the session works.** A
  review that lands during a long job is not lost, only unread: read the
  queue between jobs, not just when idle. #340's first review sat there for
  half an hour while this session believed none had come.
- **Under TypeScript 7** the generated ts SDK needs `composite` on `src`,
  a `references` entry on `test`, `tsc` resolved through
  `typescript/package.json`, and `node:module`'s `stripTypeScriptTypes`
  (Node 22.13 and later, declared as `engines.node`) in place of
  `transpileModule`. #334 has the lanes and the controls.
- **Two path lines into one entity can fail to unify.** In a generate-test
  model extra, `main: kit: entity: planet: op: create: active: false` on one
  line and the same for `update` on the next made aontu report a
  `scalar_kind` clash at `planet.relations.ancestors`, while either line
  alone, or one `op: { create: { active: false }, update: { active: false } }`
  block, unifies. #341's tests use the block form.
- **Compare survey models by meaning as well as text.** A change to a
  point's selector reorders the points in a model file, so a text diff shows
  whole points, `$action` lines included, moving between hunks. Keying each
  entity's points by op, method, path and action, and comparing their
  selectors, query arguments and request transforms and the entity's field
  names, separates what moved from what changed; voxgig/apidef#151's counts
  came from such a script.
- **A helper's name can already be taken in the file it joins.** #342 added
  a `plain` helper to every target's options code; ruby and perl already
  declared one and silently replaced it, and php refused to load ("Cannot
  redeclare"), which only the php clean lanes caught. Grep the file for the
  name before adding a helper to a port.
- **`tar` restores a file's old modification time,** and `tsc --build`, which
  decides by time, then skips the restored source as up to date, so tests
  run the build from before the restore. `touch` what was restored, or copy
  with `cp`, which stamps the current time.
- **The test-mode mock matches a list's required parameters** against the
  seeded records (`buildArgs` in the ts `TestFeature`), so a test-mode
  example that passes them must seed the same values, or it lists nothing.
- **An unseeded test-mode list is empty,** so a check over its items passes
  whatever the items would have been. #360's first clojure check did, and
  its control passed with it; seed records before checking what a list
  gives, and confirm the control fails. clojure's generated suite, the
  entity checks included, runs with `clojure -M:test --sdk-only`.
- **An apidef entity's fields span its operations.** The field step merges
  every route's request and response properties into one field per name,
  and records a per-operation difference only for the required flag or a
  carrier's type. A name that means two things in two operations has to be
  reserved, as voxgig/apidef#151 does for its carrier, rather than merged.
- **A probe script that renders through `generateharness.ts`** outside the
  test runner needs `NODE_PATH` set to `ts/node_modules`, a
  `process.chdir(H.SCAFFOLD)` before rendering, and a `Basic<Name>Flow` per
  entity in its model.
- **A full suite can run out of disk.** Here one failed with ENOSPC beside
  several worktrees and generated SDKs, and finished once stale worktrees and
  scratch copies were removed. How much space a machine or container has is
  its own fact: check `df` before a full suite rather than assume a size.
- **apidef's Go port keeps reference cycles.** The TypeScript parse cuts a
  `$ref` cycle to a `[Circular …]` string (`decycle`), but Go resolves a
  reference to the shared map and keeps the cycle. A Go walk over `allOf`,
  `oneOf` or `anyOf` needs a guard, as `enterPart` in `transform_body.go`
  gives the null rules; without one, a schema whose `allOf` named itself
  overflowed Go's stack, a fatal error no test recovers from
  (voxgig/apidef#151, `/loops`).
- **Codex has a usage limit.** When it answers `@codex review` with "You
  have reached your Codex usage limits for code reviews", no review ran, and
  the push it was asked for still needs one before the merge. Ask again
  later; each request that meets the limit gets that answer again.
- **A closing keyword in a pull request's body reaches other repositories.**
  #347's body said voxgig/apidef#151 "now also fixes voxgig/apidef#152", and
  GitHub listed #347 among the pull requests that would close that issue on
  merging. Write "takes in" or "covers" for a pull request that is not the
  fix. A page's own text closes nothing.
- **apidef resolves the guide's `@voxgig/apidef/model/guide.aontu` include
  from the running script's directory,** not the working directory. A probe
  script that builds one of apidef's test folders has to sit under `ts/test/`
  while it runs.
