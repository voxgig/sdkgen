## Working rules the user set

- **Merge when green.** A pull request opened for this work merges once CI
  passes on every OS and no review thread is open.
  - Codex reviews every PR in sdkgen, apidef, struct and sdkgen-langpack,
    usually within 15 minutes of it opening or being marked ready. A later
    push is not reviewed again unless someone comments `@codex review`.
  - Wait for that review before merging: it found real defects in most PRs.
- **Verify every review finding.**
  - A real finding is fixed with a test and a negative control.
  - Reply on each thread as the last write before the push that fixes it,
    then resolve the thread.
  - A finding that does not reproduce gets a reply saying why.
- **Merge commits.** sdkgen, apidef, struct and sdkgen-langpack PRs merge
  with a merge commit, and a branch takes main by merging it, never by
  rebasing. apidef-validate PRs are squashed.
- **Releases wait for the user.** See [Releases](#releases-waiting-for-the-user).
- **apidef commits** carry no trailers and no tool identifiers.

### voxgig/apidef#151, `claude/array-request-body`: voxgig/apidef#123

- **Change:** a JSON request body that is an array is sent from one field of
  the request data, in both ports. The operation step decides it, from the
  body the guide's `body.media` names, else the preferred JSON one; an array
  behind `allOf`, or behind a single `oneOf` or `anyOf` member beside any
  `null`, counts, and a guide's `transform.req` still wins. The field is the plural of the
  record the items name, through `allOf` parts too (`SmsMessageRequest`
  gives `sms_messages`, and `hero` gives `heroes`), prefixed with `n` before
  a digit. It is `<record>_list` when the name is taken: as an argument of
  any route of the operation, as a field any other route of the entity sends
  or answers, or as another route's carrier of a different type. A carrier keeps the array's
  own type, so a body that may be null, by a 3.1 type list or 3.0
  `nullable`, gives the one-of type. Select requires it when the body is
  required; the field step models it as an optional `$ARRAY` field, remove
  points included, and reads request properties from the body `body.media`
  names, whatever its media type. A Swagger 2 `body` parameter is read as
  the request body and is no longer a query argument. `pluralize` is new and
  keeps only a plural `depluralize` reads back.
- **Tests:** an OpenAPI 3 and a Swagger 2 definition built by both ports
  against shared expectations, and two shared TSV fixtures; each case fails
  on the commit before the round that added it.
- **Corpus:** OpenAPI 3 models unchanged; in the four Swagger 2 APIs, 579
  points lose the `body` query argument, the four array bodies unwrap, and
  495 body properties become fields. The PR body has the counts per API.
- **Review:** eight Codex rounds. Twenty-five findings were fixed
