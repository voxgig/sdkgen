## Working rules the user set

- **Merge when green.** A pull request opened for this work merges once CI
  passes on every OS and no review thread is open.
  - Codex reviews every PR in sdkgen and apidef, usually within 15 minutes of
    it opening or being marked ready. A later push is not reviewed again
    unless someone comments `@codex review`.
  - Wait for that review before merging: it found real defects in most PRs.
- **Verify every review finding.**
  - A real finding is fixed with a test and a negative control.
  - Reply on each thread as the last write before the push that fixes it,
    then resolve the thread.
  - A finding that does not reproduce gets a reply saying why.
- **Merge commits.** sdkgen and apidef PRs merge with a merge commit, and a
  branch takes main by merging it, never by rebasing. apidef-validate PRs are
  squashed.
- **Releases wait for the user.** See [Releases](#releases-waiting-for-the-user).
- **apidef commits** carry no trailers and no tool identifiers.

## Notes for the next session

- **Check the environment rather than assuming it.** Run the `command -v`
  loop in AGENTS.md before deciding what can be verified. This session's
  container had, after installing them: zig 0.16 (`pip install ziglang` and a
  wrapper on `PATH`), lua 5.4 with busted 2.2 (apt `lua-busted`, and
  `update-alternatives --set lua-interpreter /usr/bin/lua5.4`), elixir 1.14,
  ocaml 4.14, .NET 8, phpunit 11.5 (composer into scratch, symlinked onto
  `PATH`), pytest and requests for `python3`, the libssl and libcurl headers,
  and vale 3.14.0 from `make vale-install`, which lands in `.vale/bin` and is
  not on `PATH` (`PATH=.vale/bin:$PATH make scan-prose`). It had no swift,
  scala-cli, clojure, dart, lean or ghc, so those lanes skip. luarocks could
  not fetch GitHub archives through the proxy.
- **Load.** Two full sdkgen suites at once on a 4-CPU container pushed the
  load average past 10. Run one heavy job at a time. The container restarted
  twice during this session and killed every background process; files on
  disk survived, so write logs and re-run what died.
- **Node 22's default reporter** prints `# skipped N`; the spec reporter
  prints `ℹ skipped N`. `skipped()` in `livegenerated.test.ts` reads both.
- **PHP records exception arguments** (`zend.exception_ignore_args=0`) when
  no php.ini sets otherwise, as a Homebrew install and the windows-latest
  runner do; the production ini sets `On`, as ubuntu-latest does. An error's
  trace then carries every argument the failing frames were handed, the
  context included. clean strips them; the sweep now exercises that (#326).
- **The apidef corpus survey**, required for every apidef change that alters
  a model, as this session ran it (the scripts were in scratch space). It
  runs in apidef-validate's `v1`, once per side (main and the branch, each
  built with `npm run build` in its `ts/`). A side's Go step compares
  against whatever goldens are in the working tree, so each side runs all
  of its steps before the next side starts:
  1. Start the side from the committed goldens: `git checkout -- model
     guide && git clean -fd -- model guide`. The checkout alone leaves any
     golden the other side's run added as an untracked file.
  2. Point `node_modules/@voxgig/apidef` at that side's `ts/` and run
     `UPDATE_SNAPSHOTS=1 node --enable-source-maps --test
     --test-name-pattern="model-case|guide-case" "dist-test/**/*.test.js"`.
     Copy `model/` and `guide/` aside, into a fresh directory per side.
  3. With that side's goldens still in the working tree, in `v1/go`: `go
     mod edit -replace github.com/voxgig/apidef/go=<side>/go`, then
     `GOFLAGS=-mod=mod go test -count=1 -run
     'TestValidate/(model-case|guide-case)' ./...`, and restore `go.mod` and
     `go.sum`. Because each Go run compares against its own side's TS
     goldens, a difference between the two ports shows as a failing subtest
     on one side only.
  4. After both sides, restore the checkout as in step 1, so the next
     survey does not start from a side's leftovers, then `diff -r` the two
     copies.
- **Maven Central** answered the kotlin lane with HTTP 429 once. An existing
  gradle cache, used offline, got past it.
- **apidef's Go golden tests** need an apidef-validate checkout. Set
  `APIDEF_VALIDATE_DIR` to its `v1`, or they skip; with the committed goldens
  behind main (voxgig/apidef#145 changes them), they fail for that reason
  alone.
- **GitHub runs a PR's CI on its merge with main.** A PR that conflicts with
  main runs only the push-triggered comment check, so merge main first.
- **The generate suite's `SMOKE` guard** matches generated test text: adding
  a test that legitimately calls an op with arguments can trip a coarse
  regex, as ocaml's `e_load` did; narrow the regex to the bare call rather
  than drop the test.
- **A re-review is one comment away.** Codex reviews a PR once, when it
  opens; after a large fix push, `@codex review` on the PR brings a second
  review within ten minutes. On #327 it found a real defect the fix had
  missed (clojure's stream) and one non-reproducing finding. Ask for it
  after any push that touches many targets.
- **A push that produces no build runs** means the PR conflicts with main:
  only the comment check runs. Merge main, rebuild `ts/dist`, regenerate the
  golden with `npm run golden`, push. The `ts/dist` and golden conflicts are
  always resolved that way, never by hand.
- **The mock's match treats a `$`-prefixed key as required.** The struct
  `select(list, '$x')` returns the whole list, so the ts and js mocks' match
  builder took `$body` as a required match key, and would take `$action`.
  The mocks now build their match from the record without `$body`; `$action`
  through the mock's update is a latent case of the same thing.
- **The comment gate counts density per file** (12% of code lines) and flags
  a number word in a comment (`two classes`) as a count claim. Adding a
  comment to a file near the limit trips it; trim rather than argue.
- **The generate fixture needs a `Basic<Name>Flow` per entity** for the ts
  and php test components, and the base fixture already has an entity named
  `record`. `namedEntity()` in `generateharness.ts` writes a list-only entity
  with its flow.
- **A stream-capable target is found by its transport, not its media file:**
  clojure accepts an `InputStream` in `core.clj`. Grep every target's fetcher
  for the stream type before claiming a list is complete.
- **`pkill -f <pattern>` matches the shell running it** when the pattern is in
  that shell's own command line, and kills it; `pkill -f "mt2-verif[y]"`
  does not.
