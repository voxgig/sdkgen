# Design: generated text that follows the model

Status: **proposal** (2026-11-12). Nothing here is implemented. Code
references are to `main` at 9aebaf9e (4.44.0); paths are relative to the
repository root unless another repository is named.

From the review of `alongsideNote` (`ts/src/helpers/alongside.ts`), in full:

> but surely there are other similar parameterised text elements throughout
> the generated markdown documentation - this seems like a fragile special
> case - is there no general mechanism to handle this?

and then:

> design a general solution

---

## 1. The answer

There is no general mechanism today. There are partial ones: a helper per
sentence that someone noticed (`alongsideNote`, `credentialPlacement`), a
frame that writes a shared sentence once (`ReadmeIntro`, since b4cd6877),
closed wording slots (`modelText`), and one derivation the code generators
share (`configDefinition`). Nothing ties a sentence to the fact it states,
and nothing checks generated text against the model: the README example
tests compile and run code blocks, and no test reads prose, a table or a
link.

The class is large. Generating the documentation under 146 single-switch
variations of one model found 674 places where generated text depends on
the model, 53 sentences that went stale when one thing was switched off,
and at least 21 that are wrong with everything switched on (section 3).

The general mechanism has two halves. Neither works alone.

1. **One answer per fact, and one writer per shared sentence.** Every fact a
   sentence depends on comes from one exported derivation, the same one the
   code generators call for the same decision. A sentence that reads the
   same in every language is written once, in the neutral frame. A target
   says what it is in its own model file instead of being recognised by its
   key.
2. **One check that the text follows the model.** A test in sdkgen's suite
   regenerates the documentation with each thing in the model removed in
   turn. It fails when a document still names the removed thing, when a link
   points at a file the run did not write, or when one language's version of
   a section reads a fact its siblings ignore. Every `generate` checks the
   links and tables it just wrote.

A sentence-level construct (a claim registry, conditions as data, a template
language) was built and measured, and is not proposed. Ported at two real
sites it turned none of the fifteen cases in section 11 from caught into
prevented: the text is written on three paths and in 260 per-language
project copies, and a construct reaches only the code that adopts it
(appendix A).

Order of delivery: the check first, because it changes no generated byte and
protects every later step; then the derivations, byte-identical for a model
with everything switched on (measured); then the corrections, one visible
diff each.

## 2. What exists today

- **Shared derivations on the code side.** `configDefinition`
  (`ts/src/utility.ts`) is called by all twenty `Config_<lang>` generators.
  Where every writer calls one resolver the outputs agree: credential
  placement changes Config, PrepareAuth, the tests and the README together in
  20 of 20 targets. This note extends that pattern to documents.
- **Resolvers a document can already call**, all exported: `targetFeatures`,
  `serverVariables`, `isAuthActive`, `isAuthSuppressed`, `isHttpBasicAuth`,
  `originName`, `envName`, `packageName`, `goModule`, `registryState`,
  `entityOps`, `credentialPlacement`.
- **A frame and a body.** `ReadmeIntro` (`ts/src/cmp/ReadmeIntro.ts:14-32`)
  writes the title, the tagline and the sibling note once and calls the
  target's `ReadmeIntroBody` between them. A module that still exports a
  whole `ReadmeIntro` (an older project copy, a pack) is honoured unframed.
  All twenty bundled intros export the body.
- **`optionalComponent`**: a missing per-language component writes nothing.
- **Wording slots**: `main.kit.text`, read through `modelText`, closed.
- **Lanes that build or run generated code.** `CLEAN_LANES`
  (`ts/test/generatedcompile.test.ts:6117`) builds and runs a shipped test in
  all twenty targets; `SERVER_LANES` (`:6516`) runs the server-variable rule
  in six runtimes; `README_LANES` (`:8798`) runs README blocks in rb, go, lua
  and py, and ts runs its own in a separate loop; `DOC_LANES` (`:9203`)
  compiles them in c, cpp, rust, zig and ocaml. Nineteen targets ship a
  generated `ReadmeExamplesTest_<lang>`. Every one of them reads code blocks.
  None reads prose.
- **What says "this target is a consumer"** today: five phase flags in three
  target files, `isConsumer` (`ts/src/helpers/alongside.ts:8`), 24 lines in
  five core files that quote a target key, `NON_SDK_SIBLING`
  (`ts/test/generate.test.ts:120`), `CONSUMER` in the manifest's parity tiers
  (`ts/src/helpers/manifest.ts:33`), and docgen's own
  `main.kit.doc.target.<t>.kind`. The model never says it.

## 3. The problem, measured

Three shapes recur:

- **A fixed list.** A sentence names things by literal: `'go-cli'` and
  `'go-mcp'` in the sibling note, "Built-in features are `log` and `test`",
  "the same five-stage pipeline".
- **A missing gate.** A sentence is written whether or not its subject
  exists or holds: "Each is inactive until you switch it on" beside a `log`
  table that prints `active | true`.
- **A missing statement.** The code does something the documents never
  say: HTTP Basic is implemented in twenty targets and documented in one.

| Measure | Value |
| --- | --- |
| Places where generated text depends on the model | 674, in 205 files |
| Facts derived in more than one place | 73 |
| Sentences stale under 146 single-switch variations | 53, from about 30 source sites |
| Wrong with everything switched on | at least 21 |
| Dangling relative links | 85 distinct lines over the derived variations; 2 links in the all-on baseline, 100 with `main.kit.phase.top` off |
| Table rows broken by a pipe in two field descriptions | 120, in 40 files |
| HTTP Basic: targets that implement it, documents that say so | 20 against 1 |
| `server` option the runtime requires: quick starts that state it | 4 of 20 |
| Documents saying every feature starts off | 41; 40 print `log`'s `active: true` on the same page |

Where the defects are written decides who receives a fix. Of the 120
catalogued defects, 60 involve a neutral component (`ts/src`, 43 of them only
there), 60 a per-language project copy (36 only there), 10 a fragment, 11 a
copied template and 10 docgen. The five that sit only in a fragment or a
template are run-time strings and comments of the consumer targets. A fix in a
neutral component reaches every project at its next generate after the pin
moves; a fix in a copy reaches it only when the project re-adds.

## 4. The rule for whoever writes a sentence

A sentence whose truth depends on the model:

1. **Goes in the neutral frame** when it reads the same in every language,
   and into the per-language copies only when its wording is the language's
   own. Then it goes into every language that has the section.
2. **Is conditioned on an exported derivation** (section 6): never on a
   literal target key, an inline model expression or a table indexed by
   `target.name`. When no derivation answers the question, add one beside
   its kin, export it, and make the code generator that decides the same
   thing call it too.
3. **Writes nothing when the answer is unknown.** A link comes from
   `docLink`; `undefined` drops the sentence.
4. **Passes vendor text through `mdCell` or `mdInline`.**
5. **Is never written in a copied template.** A fragment receives a
   model-dependent string from its component as a replace token.
6. **Is held by the text guard** (section 7): build, run the suite, then fix
   or pin what it reports.

One statement covers the three write paths: a model-dependent string is
written by code that runs at generate time and reads the fact, and a file
that is not code holds none. `Content` in a component is such code, and so is
a fragment's replace handler. A copied template is substituted at
`target add`, with no code at generate time, so it states nothing that varies
with the model.

The frame has a limit. It works for text at a section's edge (a title, a
lead-in, a closing note), as `ReadmeIntro` shows. A block in the middle of a
ninety-line `Content` stays in the copies; sibling parity (section 7) holds
it there.

The agent guide's "Where do I make this change?" table gains one row stating
this rule.

## 5. What a target declares: `surface` and `consumes`

One fact a document needs is not in the model: what kind of thing a target
is, and which target it builds on. Two slots join the target block, after the
provenance slots at `ts/model/sdkgen.aontu:96-98`:

```
main: kit: target: &: {
  surface:  *'' | string
  consumes: *'' | string
}
```

They carry no comment in the schema. The base schema sits at the comment
gate's density limit, and one commented line there fails `npm test`
(measured: 12.3% against 12%). Their meaning goes in
`docs/reference/model.md`.

- **`surface`** is `sdk`, `cli`, `mcp` or `data`. It is open in the schema and
  closed in code, the form `provides` and `TAGS` already take: a `SURFACES`
  constant; `package check` reports any other word as an error; `generate`
  reads an unknown word as an unnamed consumer and never fails. An empty
  value means undeclared.
- **`consumes`** names the origin of the target this one builds on (`go`).
  The derivation returns the installed keys with that origin. When there are
  two (`go` and an alias of it), the consumer's own file names one by
  installed key, or generation stops and names both.

The names avoid two words already in use. A feature's transport `role` is
`ts/src/types.ts:42`, and a feature's `wraps` is a boolean
(`ts/src/cmp/FeatureDocs.ts:14`). "Surface" is the root README's own word for
these targets (its `## Surfaces` section, `ts/src/cmp/ReadmeTop.ts:424`) and the
name of docgen's function for the same question.

**One absence rule**, for every target:

1. the declared slot;
2. else, for a target that resolves to the bundled scaffold, its origin's row
   in a frozen `LEGACY_SURFACE` table, which lists the three bundled consumers
   and which a test holds equal to their files (decision D2);
3. else `sdk` for a target that generates entities;
4. else unknown, which writes no sentence about the surface. The target is
   then named by its title, never as "the CLI".

The answer records which step gave it. An alias reaches the legacy table
through its recorded `origname`, which matters because an alias's model file
is written once and never refreshed.

**What becomes of the other statements.** `isConsumer` is deleted (it is
`'sdk' !== surface`). `NON_SDK_SIBLING` and the test lists are read from the
scaffold's target files. `package check` requires `parity: CONSUMER` to agree
with a surface other than `sdk`. docgen's own table goes when docgen adopts
the derivation. The `delegates` tag proposed in `feature-tags.md` is
`surface` other than `sdk` and needs no slot of its own.

**Copies older than the slot.** No shipped target model file from v1.3.7
parses under today's aontu (it uses `//` comments), and component trees from
before v4.23.0 fail the strict compile against today's package with 424 to
808 errors each (both measured). The oldest copy a project can still generate
from is therefore v4.23.0. The legacy table is needed for aliases and for
copies between that floor and the release that adds the slot.

## 6. The derivations added

Each is a pure function of the compiled model, exported from
`ts/src/sdkgen.ts`, placed beside its kin, and called by every writer that
makes the same decision: documents, code generators and docgen. There is no
record object and no second access path.

```ts
// ts/src/helpers/packageMeta.ts, beside originName
type TargetSurface = {
  surface: string        // 'sdk' | 'cli' | 'mcp' | 'data' | '' (unknown)
  consumes: string       // origin name, or ''
  consumed: string[]     // installed keys with that origin, sorted
  from: string           // 'slot' | 'legacy' | 'entity' | 'unknown'
}
function targetSurface(model: any, name: string): TargetSurface

// ts/src/helpers/applicability.ts, beside targetFeatures
function featureOnByDefault(model: any, name: string): boolean

// ts/src/utility.ts, beside isHttpBasicAuth
type RequiredOptions = {
  apikey?: { env: string }   // auth active
  secret?: { env: string }   // HTTP Basic, header placement, auth not suppressed
  server?: { vars: Array<{ name: string, dflt: string, required: boolean }> }
}
function requiredOptions(model: any): RequiredOptions

// ts/src/helpers/place.ts (new)
function targetPlace(model: any, name: string): 'folder' | 'root' | 'external'
function docLink(ctx$: any, target: any, doc: string): string | undefined

// ts/src/helpers/markdown.ts (new)
function mdCell(text: string): string
function mdInline(text: string): string

// ts/src/helpers/copymerge.ts, beside copyMode
function modelCopyMode(model: any): 'merge' | 'overwrite'

// ts/src/sdkgen.ts
function guardModel(model: any, log: any): void
```

| Derivation | Replaces |
| --- | --- |
| `targetSurface` | the quoted keys in `ts/src/helpers/alongside.ts:20-23`, `ts/src/cmp/ReadmeTop.ts:146-172` and `:450-453`, `ts/src/helpers/mcpTools.ts`; `isConsumer` |
| `featureOnByDefault` | the expression at `ts/src/cmp/AgentGuideFeature.ts:31`, today the only correct one; the four "starts off" sentences |
| `requiredOptions` | `isHttpBasicAuth` alone in five ts README components; the composition each language writes by hand |
| `targetPlace`, `docLink` | literal `../README.md` and `../AGENTS.md`; `cd <dir>` literals |
| `modelCopyMode` | `model.main?.kit?.copies` at `ts/src/cmp/ReadmeTop.ts:614`, which also bypasses `KIT` |
| `mdCell`, `mdInline` | raw vendor text in table cells and prose |
| `guardModel` | lets docgen apply to `sdk.json` the renames `generate` applies (section 9) |

Notes on each:

- **`secret` is Basic AND header placement AND not suppressed.** Measured
  over twenty targets and eight auth states (160 generated PrepareAuth
  files): the Basic branch is present exactly then. Twelve generators gate on
  `basic && 'header' === where` and eight reach the same result by dispatch.
- **`requiredOptions` computes "referenced" itself** rather than adding a
  field to the return of `serverVariables`. The added field changes no
  generated byte but fails three exact-shape tests
  (`ts/test/helpers.test.ts:566-599`).
- **"Required" is what the runtimes do**: a variable the URL references and
  the spec gives no default. Test mode and a literal `base` are the
  exceptions. The same rule was read in the twenty bundled runtimes and in
  dart and haskell; lean has none.
- **`docLink` answers from the pass it runs in.** It returns `undefined` in an
  out-of-tree pass for a root document, which that pass does not write, and
  when `main.kit.phase.top` is off. `targetPlace` gives the declared layout,
  and a caller with no pass uses it. `output.path: ''` is undeclared;
  `ts/src/action/remove.ts:293` tests for `null` and so misreads it (section
  14).
- **`targetOrigins` gains a third answer**: bundled, external or owned. Owned
  is decided where `Source.owned` is decided today (`ts/src/action/resolve.ts`).
  A real `target add` records a non-empty `base` for a bundled target too, so
  "empty `base` means bundled" is wrong (measured), and no second provenance
  rule is written.

A test holds the derivations to the code side. The features
`targetFeatures` reports equal the keys of
`configDefinition(m, t).def.feature`, and `featureOnByDefault` equals each
entry's `options.active` (measured: passes for 115 target checks over five
fixtures). `secret` is held by generated output (the generated PrepareAuth
reads the option exactly when `secret` holds), because Config says
`basic: true` under any placement.

## 7. The text guard

**Where.** `ts/test/textguard.ts` with `ts/test/textguard.test.ts`, internal
to sdkgen's suite. Nothing is exported until a pack asks (decision D4).

**Harness.** A Root that follows the real plan: root documents only when
`main.kit.phase.top` is on, inactive targets skipped, consumers through their
`Main`. A docs-only mode generates in 0.73 s against 2.74 s for the full Root,
and its 171 documents are byte-identical to the full Root's (measured). The
harness keeps the jostraca tree itself: `generate()` holds it in a local
(`ts/src/sdkgen.ts:380`) and returns `{ ok: true, name: 'sdkgen' }`
(`:441`).

**Variations.** Derived from the compiled model; none is listed by hand:

- each target, feature, entity and operation removed;
- the empty and the lone state of each kind;
- auth off, bearer, Basic in the header and Basic in the query;
- a plain server URL, and a templated one with and without defaults;
- each document phase off.

A variation is an edit of the model source, because unification cannot remove
(appending `active: false` to a bundled feature fails to unify, measured).
The fixture yields 148 variations.

**Relations.**

| Relation | A finding is | Word list | Measured on today's output |
| --- | --- | --- | --- |
| `link` | a relative link, anchor or `cd` in a generated document that does not resolve in the tree that run wrote (`.sdk/` counts as present; `cd` from the document's directory or the tree root) | none | 85 distinct lines, every one real, none false |
| `off` | a line, in the run without X, that names X | derived from the model, plus a small synonym table | recall 41 of 53 catalogued stale sentences (36 without synonyms); 35% precision before pins |
| `parity` | per-language siblings of one section read different model facts | none | 9 of 114 sibling pairs split, among them the `server` option and HTTP Basic omissions; generation 14% slower |
| `reaction` | a line that leaves one language's document under a variation and survives verbatim in a sibling | none | 5 benign findings over 142 variations; it speaks once the first sibling is fixed |

`off` derives its words from the model: the key in backticks and as a path
segment, the title, the generated class names, and the surface words ("CLI",
"MCP") once `surface` is declared. Without the surface words the
reintroduced pre-fix sibling sentence is not reported, because the model's
title is "Go MCP server" and no document writes that (measured); today only a
hand-written synonym finds it. A synonym is admitted only
when it raises no false finding in the run that removes its subject: "AI
agent" fails that test on "for both humans and AI agents".

`parity` is the house rule on language parity stated as a test. The guard
hands `generate` a Proxy of the model and attributes each read to the
component being built. It needs one sibling to be right, and a deliberate
divergence is a pin with a reason. It sees omissions; `off` sees mentions;
`reaction` sees a fix that reached one language and not the rest.

Exact checks join the guard one at a time, each in the commit that corrects
what it guards: a fence tag in a target's document is that target's language
or a neutral one; no fragment marker line survives into output; no table
header stands without rows; a sentence says features start off only when
every feature it covers does.

**Pins.** A pin is keyed on (relation, the chain of labelled components that
wrote the line, cause), with the line kept as evidence. A pin that matches
nothing fails, as stale allow-list entries fail the dependency gate. Keyed on
exact lines, today's output needs 828 pins, because a sentence carrying the
language's name is a different line in every language. Keyed on the writing
component it needs 101: 56 known stale, 25 generic words, 16 true by
construction and 4 undecided (measured). A family whose meaning is undecided
(operation-level `active: false`, decision D1) is suspended as one entry with
its reason; its 409 distinct lines are not pinned one by one.

**Attribution.** 130 of 171 documents are written by a single component
chain. The root README has 398 lines directly under `ReadmeTop`, and root
`AGENTS.md` 207 under `AgentGuideTop`. Those two split into labelled
sub-components, with byte-identical output, before pins there are keyed on
the writer.

**Fixture.** The generation fixture names entities `console`, `record` and
`utility` on purpose, to collide with generated code. They collide with the
mention scan too (50 false lines). The guard's overlay replaces every vendor
string (entity and field names, paths, flow names, descriptions, `info`,
`main.kit.text`) with opaque tokens.

**Negative control.** A test-only component writes a stale sentence, a
dangling link and an unfired marker. The guard must report exactly those
three more findings, and in the prototype it did.

**Cost.** 148 variations take 168.6 s to generate and 198.3 s with the
relations, in one process (minimum of three runs on a shared four-CPU
machine). The full matrix runs in one CI lane; `npm test` runs `link` on the
baseline and a fixed subset.

**What a false positive costs an author.** A correct sentence that names an
absent thing to say it is absent ("exposes no list or load operations") is
reported. Its pin is one per writing component.

## 8. The check every generate runs, and the escapers

After each pass, `generate` checks the `File` nodes of the tree it kept. Their
text is present even under dry run (835 of 835 files, measured). Two exact
checks run:

- every relative link and anchor resolves in what the pass wrote;
- every table row is well formed: it ends as its header ends and belongs to a
  table with a header. A cell count alone misses the 60 rows that one line
  break in a description cuts.

Findings are warnings in the house form
(`log.warn({ point: 'doc-link-dangling', ... })`,
`point: 'doc-table-broken'`), which a project's `npm run generate` prints.
sdkgen's own suite fails on them. No environment variable switches this. No
word scan runs here, because on a real API vendor prose would swamp it.

This is the only check that sees a project's own copies, aliases, packs, an
older Root and a run override. The eight template READMEs that a `Main` copies
into `ts/` and `js/` have no `File` node and are not seen. The check costs
0.19 s per tree of 175 documents, unoptimised.

**Escapers** go in `ts/src/helpers/markdown.ts`:

- `mdCell` turns a pipe into `\|` and a line break into `<br>`;
- `mdInline` turns a line break into a space;
- both turn `$$` into `$&#36;`, which survives the template pass (measured).
  They use a function replacer, because `$&` in a replacement string means
  "the match".

Today two descriptions containing a pipe break 120 table rows, and one line
break cuts 60. `$$name$$` in a field description is substituted in 60 table
cells, and in 20 of 22 generated source files, a code defect listed in
section 14.

## 9. Copies, consumers, packs, docgen

**Per-language copies.** The 260 `Readme*_<lang>.ts` components stay where
they are. A fix in them reaches a project through
`voxgig-sdkgen package update @voxgig/sdkgen`, which moves the tilde pin and
re-adds in one act (measured: `~4.42.0` to `~4.44.0`, two copies refreshed,
doctor clean), or through `target add`. A project that moves its pin by hand,
or by a re-scaffold naming no targets, gets the neutral corrections and the
generate-time warnings. Doctor then reports its copies outdated until it
re-adds.

Rules for a wave of copy changes:

- A new helper arrives as a new file, never as an addition to an existing
  copied file in the same wave as its first use. Measured: a project that had
  edited `utility_ts.ts` and resolved the conflict with `--keep` was left
  with a tree that doctor passed and `tsc` refused (TS2305).
- A project with no copy record (its last add predates 4.34.0) sees moved
  copies as forked, and the add refuses them. The safe path is to commit, then
  pass `--force`, never `--keep`.
- The neutral corrections are safe for old copies. All 23 targets were
  generated from v4.34.2 copies under 4.44.0 with the stage-2 corrections
  emulated. Every own-language block the old README tests read stayed
  byte-identical, and the old rb and go suites stayed green.

**Consumer `Main`s.** go-cli registers its words from one literal
(`ts/project/.sdk/src/cmp/go-cli/fragment/words.fragment.go:13`) and prints
them from another (`ts/project/.sdk/src/cmp/go-cli/fragment/main.fragment.go:37`).
Both take one value derived from the model's operations. This was built:
go-cli is byte-identical
for an all-on model, `--help` follows the model with `update` off, and the
result compiles. The MCP `load` description `{"id":1}`
(`ts/project/.sdk/src/cmp/go-mcp/Main_go-mcp.ts:63,87`) sits beside
`toolExample` (`:101`), which already computes the right value per entity
through `matchArg`. One tool serves several entities, so the description
gives the per-entity form.

**Packs.** The language pack runs at its floor (4.34.2) and at head. Every
resolver section 6 builds on is exported at 4.34.2 (236 exports there, 278 at
4.44.0, none removed). A new derivation is read through a namespace import
with a fallback, because a named import of a newer export is TS2305 at the
floor. The literal sibling sentence in sdkgen-langpack's
`.sdk/src/cmp/dart/ReadmeIntro_dart.ts:56` and
`.sdk/src/cmp/haskell/ReadmeIntro_haskell.ts:58` goes away when the module exports
`ReadmeIntroBody` (the introduction without title and tagline) beside a
`ReadmeIntro` that writes them and calls the body. This was measured at
4.34.2, 4.41.1 and 4.42.0 (no note) and at 4.43.0 and 4.44.0 (framed, with the
generated note), and it strict-compiles at both ends. Exporting one function
under both names writes the title twice at head, and the pack's suite passes
it. The pack declares `surface` and `consumes` in its target files, and the
4.34.2 schema ignores them (measured). The infrastructure pack's
`seneca-provider` (floor 4.33.0) is the first packaged consumer and declares
them the same way.

**docgen.** docgen reads its own `kind` first, as a presentation override,
then `targetSurface` when the sdkgen it resolves exports it, and its present
table otherwise. Standalone, it reads `sdk.json`, which `@voxgig/model` writes
before `generate()` runs its model guards. Measured: the CI-regenerated
edition names `Planet` and `3dsSession` where the SDK has `Planet2` and
`N3dsSession`. docgen applies `guardModel` to what it reads. Its standalone
command passes no logger, so a fallback notice needs one.

**The root plan.** Six statements of it exist: the scaffold's `RootPlan.ts`
and `Root.ts`, `defaultRoot` in `ts/src/testkit.ts`, the suite's `makeRoot`,
the scaffold's drift script and the pack's docs Root. They disagree on root
documents, `target.active` and `output.root`. In the one-home arrangement,
sdkgen exports `rootPlan`, the scaffold's Root imports it in the release that
moves its pin, and the rest call it.

Stage 1 was prototyped with the derivations gathered in a record object; the
reads are the same. With everything switched on, 7 of 7 fixtures were
byte-identical, and so were 11 single-switch variations. The suite passed
after three test edits (2,525 pass, 0 fail, 5 skipped). One finding binds the
stage: under a run override the ported note named a surface that the same
run's root README omits. Until decision D3, a note speaks of what its own pass
writes.

The stage-3 lane model costs fourteen lines and covered ts, rb and go in 10 s.
No README lane model today has auth on or a templated URL, so no lane has ever
rendered a constructor field.

Each stage that changes `ts/src` is a minor release. Across repositories the
order is sdkgen, then the packs and docgen, then create-sdkgen's pin. Other
work currently owns the next create-sdkgen release, and nothing here assumes
when its pin moves.

For comparison, correcting the 30 or so source sites by hand fixes today's 53
sentences and stops none from recurring. Stages 2 and 3 make the same

recurrence.

## 12. Decisions for the maintainer

**D1. What operation-level `active: false` means.** apidef never emits it: 0
of 1,966 model files from 18 APIs in the validation goldens carry it, and a
guide entry removes the operation before sdkgen sees the model. No schema
declares it. Documents honour it in part and the code ignores it, so the
generated ts entity still has `remove`, and calling it resolves.
*Recommendation*: an inactive operation is an absent one. A pre-pass before
Root removes it. Built: output identical to a never-declared operation in five
states, and 316 of 316 tests in the affected suites pass. The schema declares
`op: &: active: *true | boolean`, the flow guard reports the dropped step as
information, not as a defect, and `guardModel` carries the pass to docgen. A
project already using the switch sees 138 generated files change.

**D2. Where `surface` lives for the three bundled consumers.**
*Recommendation*: in their own model files, with `LEGACY_SURFACE` answering
only for older copies. Measured cost: doctor exits 1 with three outdated files
in a project that changed nothing, until `package update` refreshes them
without `--force`; a project's edited copy takes the change by merge; the
add-output golden moves by three lines. The alternative, where the table
answers for the bundled consumers and their files stay as they are, changes no
copy. But it leaves the model silent about the only consumers sdkgen ships
(`sdk.json` carries an empty surface for all three), and it makes the table
the home rather than a compatibility reading.

**D3. In-tree documents under a run override.** Today `SDKGEN_EXTERNAL` alone
changes 31 lines of the root README on the 23-target fixture, and changes the
in-tree sibling notes. *Recommendation*: documents committed in the SDK
repository follow the declared layout, and an override changes none of them,
which is why the override exists. A prototype of 85 lines in four source files
made `README.md` and `AGENTS.md` identical for 22 of 22 relocatable targets.
It needs the override-only target set on `meta` and the declared model on
`ctx$.model` for project-level components (a local copy printed default
package names); `.sdk/PUBLISHING.md` and the sibling notes need the same.
Relocating `py` fails the run today, with or without this.

**D4. Whether the text guard becomes public testkit API.**
*Recommendation*: not until a pack asks. When one does, the pack skips by
version (below the release that exports the guard) and not by name, because a
renamed export would then skip silently at head.

**D5. Whether the rule earns an ADR**: "generated text states only what the
model declares, and an unknown answer writes no sentence". *Recommendation*:
yes, with stage 1.

**D6. Scope beyond markdown.** The request named generated markdown.
*Recommendation*: include the two consumer run-time strings, which are the
same defect at the same sites. Leave source comments to a pass that removes
model-specific claims from them, without a gate.

## 13. Defaults taken

- **Test mode.** Every `target add` installs `test`
  (`ts/src/action/target.ts:131-134`), and `feature remove test` is refused
  (`ts/src/action/remove.ts:179`). A project without the feature has
  hand-edited its model. Its SDK compiles and then fails at run time (ts at
  construction, go on every request), and its own suite goes red (ts 49
  tests, go 29). So `generate` and doctor report an error naming
  `target add <t>`, and no document is gated on the feature.
- **Warnings.** A project gets warnings; sdkgen's suite fails on them.
- **No capability vocabulary.** A neutral sentence about constructor options
  is not written: it would be false for two packaged targets (haskell has no
  `secret`; lean has neither `secret` nor `server`). Each quick start prints
  what its own runtime takes.
- **Vendor text never fails a build.**
- **Packs keep their floors.**
- **docgen keeps `kind` first** for its editions.

## 14. Found while designing

These defects were found on the way. Each sits beside the class or in it, and
none is fixed by this note.

1. `sdk.json` is written before `generate()` renames entities, so the edition
   docgen regenerates from it names entities the SDK does not have.
2. Config says `basic: true` under query and cookie placement in all twenty
   targets (`ts/src/utility.ts:388`), and no PrepareAuth reads it there.
3. Twelve of twenty PrepareAuth generators carry their own copy of the
   suppression test instead of importing `isAuthSuppressed`.
4. Thirty per-language components pass `target.name` where a language is
   meant (`canonToType(field.t, target.name)`, for example
   `ts/project/.sdk/src/cmp/go/ReadmeEntity_go.ts:92` and
   `ts/project/.sdk/src/cmp/go/ReadmeRef_go.ts:206`), so an aliased language
   documents every field as `any`. The code side passes the language
   (`ts/project/.sdk/src/cmp/go/EntityTypes_go.ts:63`).
5. Wording tables indexed by `target.name`
   (`ts/src/cmp/ReadmeErrors.ts:212`, `ts/src/cmp/ReadmeExplanation.ts:225`)
   give an aliased Go README the TypeScript row.
6. go-cli and go-mcp generate without `go` and still point at `../go`; py-data
   refuses the same state. With `go` aliased, go-cli's `go.mod` still says
   `replace ... => ../go` (`ts/project/.sdk/src/cmp/go-cli/Main_go-cli.ts:358`).
7. `ts/src/action/remove.ts:293` tests `null != output?.path`, while the
   schema default is `''`, so the out-of-tree note prints for every in-tree
   target.
8. Root `AGENTS.md` says "`generate` **merges** into existing files"
   (`ts/src/cmp/AgentGuideContent.ts:137`); generation overwrites.
9. A default project has no `log` feature, yet "Built-in features are `log`
   and `test`" (`ts/src/cmp/AgentGuideContent.ts:189`). The `test` feature model's
   comment, copied into every project, says "Test mode is not active by
   default, unlike most features"
   (`ts/project/.sdk/model/feature/test.aontu:13`), while 19 of 20 features
   start off.
10. The base schema's hook list names `PreTarget` and `PostOperation`
    (`ts/model/sdkgen.aontu:241,246`), which nothing uses. It omits
    `PrePoint`, `PreDone` and `PreUnexpected`.
11. 33 code blocks in the js documents are tagged `ts` (12 of 27 in the
    README, all 21 in the REFERENCE).
12. A parenthesis anywhere in the printed rb constructor, even in a comment,
    fails the generated rb README test, whose constructor match is
    `[^()]*`.
13. Documented commands can leave a project unable to generate: package
    update, then a re-scaffold with an older create-sdkgen and `--force`. The
    pin goes back, the copies stay newer, and `generate` stops with TS2305.
    Doctor calls the newer copies outdated and prints a command that would
    replace them with older ones.
14. The language pack's floor lane fails `check-package` on a fresh install:
    `shape` resolves to 12.1.0 and the 4.34.2 CLI imports `One` from it.
15. `$$` in vendor text is substituted in 20 of 22 generated source files.
16. The agent guide lists `ocaml` among the untrimmed targets;
    `ts/project/.sdk/model/target/ocaml.aontu:45` says `trim: true`.

## 15. What no check here sees

- Run-time truth beyond the existing lanes.
- A claim that names nothing removable and has no sibling, such as "All
  entities share the same interface".
- A fact nobody declares: a packaged target with no `surface` is named by its
  title, correctly but vaguely.
- Words in a real project's output; at generate time only links and tables
  are checked.
- Copies a project never re-adds.
- Markdown that a `Main` copies as a template, at generate time.
- Reads hidden behind the nine model-keyed memos in `opShape.ts` and
  `naming.ts`, which `parity` attributes to whichever section asks first.
- Combinations of switches beyond the empty and lone states.

## 16. Non-goals

- No sentence registry, claim catalogue, template language, or conditions
  held as data.
- No change to jostraca, `Content`, `File` or `Fragment`.
- No scaffold file retired. No section split into more than a frame and a
  body.
- No fact record object. Derivations are functions.
- No closed set in the schema.
- No change to generated code beyond D1 and the two consumer strings.
- No word scan of a project's output at generate time.
- The run plan is never written to the model, to `sdk.json` or to a log.

## Appendix C. How the numbers were obtained

with Node 24 and aontu 0.76.3, on a shared four-CPU machine. Timings are the
minimum of three runs. The counts of sites, facts and stale sentences come
from generating the documentation of the generation fixture under 146
single-switch variations and reading every difference. The figures for
stages 1 and 3, decision D1 and decision D3 come from prototypes built on
that commit and run against its suite. Older copies came from the release
tags, and from registry tarballs for 4.42.0 to 4.44.0. None of the prototype
code is committed.
