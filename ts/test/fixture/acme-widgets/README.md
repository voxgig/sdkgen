# `@acme/sdkgen-widgets` — the fixture sdkgen package

A **complete, checked-in sdkgen package**, used as a test fixture and
nothing else. It is never published and never installed by a real project.

Specified by §15 of
[docs/design/sdkgen-packages.md](../../../../docs/design/sdkgen-packages.md).

## Why it exists as a real tree, and not as code that builds one

`package.test.ts` synthesizes its `@acme/sdkgen-iot` fixture at runtime by
copying the bundled `go` target and renaming it. That is a good way to get a
*working* target cheaply, and it stays — it covers the add / update /
collision paths well.

What it cannot cover is the thing an external package actually is:

- **A package's own components never get type-checked.** `check-scaffold`
  compiles `project/.sdk/src/cmp/**` and nothing else. A synthesized fixture
  is a copy of sources already checked in their original home, so it proves
  nothing about a *package-shaped* component tree — and a package's
  components are exactly the code that has no other lane.
- **A synthesized fixture cannot be wrong in the ways real packages are
  wrong.** It is generated by the same repo that consumes it, so it agrees
  with sdkgen's conventions by construction. This tree is written by hand
  against the published contract, which is what a third-party author has.
- **It is the readable answer to "what does a package look like?"** The
  authoring guide can point at a directory instead of describing one.

## What is in it

| | |
|---|---|
| `.sdk/model/target/wtest.aontu` | a tiny language target — `.wt` files, `#` comments |
| `.sdk/model/feature/wfeat.aontu` | the package's own feature |
| `.sdk/model/docs/wcat.aontu` | a docs item (the third kind) |
| `.sdk/src/cmp/wtest/` | `Main` / `Entity` / `Test`, the three a target must dispatch |
| `.sdk/src/cmp/docs/wcat/` | `Main_wcat`, the docs item's emitter |
| `.sdk/tm/wtest/` | the target's template tree, including its feature container |
| `.sdk/tm/ts/` | `wfeat`'s **overlay** for the bundled `ts` target |
| `.sdk/tm/docs/wcat/` | the docs item's (optional) template tree |

Three things are deliberate:

1. **`tm/wtest/feature/` ships source for `retry`** — a feature this package
   does not own. That is what a real language package does (it implements the
   standard feature set rather than redefining it) and it is what makes the
   consumer-side trim catalogue testable: `retry` must be trimmed away for a
   consumer that does not select it, and survive for one that does.
2. **`wfeat` reaches `ts` through an overlay and `wtest` through the target's
   own tree.** Those are the two different code paths in the fan-out
   (`action/feature.ts`), and a fixture exercising only one of them leaves
   the other unproven.
3. **`targetsSupported` and `parity` are declared** even though (as of this
   writing) nothing reads them. When the test kit starts reading the manifest
   instead of `ts/test/parity.test.ts`, this is the package that proves it.
